01 / Project OverviewFoundation
Purpose & scope

Security monitoring, built hands-on.

The project builds and documents a small SOC-style environment where endpoint events can be collected centrally, reviewed through Wazuh, and used as the basis for detection and incident-response exercises.

Project objectives

  • Collect and centralize security events from enrolled endpoints.
  • Review alerts and investigate suspicious activity in a controlled lab.
  • Document configurations, detection logic, evidence, and lessons learned.

Learning outcomes

Endpoint VisibilityUnderstand agent onboarding and agent-to-manager communication.
Alert TriageReview events, interpret alert details, and prioritize investigation steps.
Detection FundamentalsLearn how rules, event fields, and test cases support detection validation.
Technical ReportingMaintain clear investigation notes and repeatable documentation.
Scope note: This is an educational home lab, not a claim of production-scale enterprise deployment. Document actual configurations and results as they are verified in your environment.

03 / Core CapabilitiesProject modules
Technical coverage

What this lab covers.

The project is organized into focused modules for hands-on practice, evidence capture, and technical presentation.

01 · Log analysis

Review Windows, Windows Server, and Linux events. Identify notable activity and record the evidence supporting the analysis.

02 · Detection rules

Maintain custom Wazuh rules and document rule logic, matching conditions, test cases, and expected alert behavior. Validate rules against observed lab events.

03 · Threat detection

Run controlled simulations and check whether relevant endpoint telemetry and detections are generated. Record test conditions and outcomes.

04 · Incident response

Follow a repeatable process: validate the alert, scope affected assets, collect evidence, document response actions, and record closure findings.

05 · Dashboards and evidence

Capture dashboard views and investigation screenshots to make the work easier to review, demonstrate, and reproduce.

06 · Scripts and reports

Organize helper scripts, configuration notes, lab reports, and supporting artifacts alongside the technical documentation.

Keep examples and screenshots tied to real lab observations.04 / 06
04 / Operational WorkflowSOC practice cycle
Repeatable process

A structured SOC practice cycle.

Use the same sequence for each lab exercise. A consistent workflow makes results easier to verify and report.

01

Deploy & connect

Prepare the virtual environment, configure the Wazuh server, enroll agents, and confirm that endpoint events are arriving.

  • Check agent status and connectivity.
  • Confirm expected event sources are enabled.
  • Record relevant versions and configuration changes.
02

Generate & detect

Perform an authorized test action and inspect the telemetry and alerts produced by the lab.

  • Record the test time and endpoint.
  • Review alert details, rule IDs, and event fields.
  • Compare observed behavior with expected detection behavior.
03

Investigate & report

Turn the alert into a concise investigation record supported by evidence.

  • Build a timeline and identify affected assets.
  • Capture relevant logs and dashboard screenshots.
  • Document findings, response actions, limitations, and lessons learned.
Investigation principle: Separate observed facts from hypotheses. Include timestamps, host identifiers, relevant event fields, and the evidence used to support each conclusion.
