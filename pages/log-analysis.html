02

Windows Security Event Reference

Common Windows event IDs useful during authentication and account investigations.

Event ID Event Name Meaning Investigation Use
4624 Successful Logon A logon session was successfully established. Review account, logon type, source address, and time.
4625 Failed Logon A logon attempt failed. Investigate repeated failures, account names, and source hosts.
4634 Logoff A logon session was terminated. Correlate session activity and logon identifiers.
4648 Explicit Credentials A logon was attempted using explicitly supplied credentials. Examine the account, process, and target server.
4672 Special Privileges Special privileges were assigned to a new logon. Review privileged sessions and account context.
4688 Process Creation A new process was created. Review process names, command lines, and parent processes.
4720 User Account Created A user account was created. Identify the creating account and the new user.
4728 Member Added to Global Group A member was added to a security-enabled global group. Review privileged group membership changes.

Event availability depends on Windows audit policy, system configuration, and the log collection settings configured for the Wazuh agent.

03

Sysmon Event Reference

Review endpoint telemetry used for process and network investigations.

Event ID Event Name Collected Information Analysis Focus
1 Process Create Process image, command line, parent process, and hashes when configured. Process execution and suspicious commands.
3 Network Connection Process-related network connection information. Destination IP, ports, and processes.
7 Image Loaded Module or image loading events when configured. Unusual module loading and process behavior.
10 Process Access One process accessing another process. Investigate suspicious cross-process access.
11 File Create File creation or overwrite activity. Review created files and their paths.
22 DNS Query DNS query activity associated with processes. Investigate queried domains and processes.

Sysmon events are recorded in Microsoft-Windows-Sysmon/Operational. Event generation depends on the installed Sysmon configuration.

05

Log Investigation Queries

Example queries for investigating events in the Wazuh dashboard.

Windows Failed Logons

Windows Security 
data.win.system.eventID: "4625"
Search for Windows failed logon events. Field availability and query syntax depend on the Wazuh dashboard index mapping.

Sysmon Process Creation

Sysmon 
data.win.system.channel:
"Microsoft-Windows-Sysmon/Operational"
AND data.win.system.eventID: "1"
Search for Sysmon process creation events. Confirm the field names using the actual indexed alert documents in your environment.

Linux SSH Authentication

Linux 
rule.groups: "authentication_failed"
Illustrative search for failed authentication alerts. Wazuh rule groups and indexed fields vary according to the matched decoder and rule.

Higher-Level Alerts

Wazuh Alerts 
rule.level: [10 TO 15]
Example range for reviewing higher-level alerts. This is not a determination that every matching event is malicious.
06

SOC Investigation Workflow

Follow a repeatable process when investigating security events.

01

Identify the Event

Locate the alert or event. Record its timestamp, source host, event ID, and affected account.

02

Collect Context

Review the source IP, process information, user, logon type, and surrounding events.

03

Correlate Events

Search related events across the relevant time window and monitored endpoints.

04

Document Findings

Record evidence, conclusions, uncertainty, and escalation or response actions.
